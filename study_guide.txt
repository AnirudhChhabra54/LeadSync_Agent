LeadSync Agent - Complete Project Study Guide

1. PROJECT OVERVIEW
-------------------
LeadSync Agent is a production-ready, AI-powered conversational agent designed to seamlessly digitize physical visiting cards, manage sales contacts, and append voice notes directly into a Google Sheets CRM. It uses a modern asynchronous backend (FastAPI) and a React frontend, orchestrated by LangGraph for human-in-the-loop workflows.

2. CORE FEATURES
----------------
- Multimodal AI Extraction: Uses Google's `gemini-flash-latest` vision model to extract Name, Phone, Email, Company, and Designation from an image of a visiting card into structured JSON.
- Human-in-the-Loop (HITL) Confirmation: Pauses the automated workflow to allow users to review, edit, or reject the extracted details on the frontend before saving.
- Intelligent Deduplication: Checks the Google Sheet for existing contacts using normalized phone numbers and emails to avoid duplicate entries.
- Background Company Enrichment: Uses LLM reasoning to infer the company's website or LinkedIn presence.
- Audio Voice Notes: Allows users to record an audio note about the meeting. The agent transcribes it, summarizes it, uploads the raw audio to Cloudinary, and links both the URL and summary to the corresponding Google Sheets row.
- Session Management: Uses MongoDB to maintain context across page reloads and parallel conversations.

----------------------------

Backend:

- Google Gemini API (`gemini-flash-latest` for Vision & Audio tasks)

Databases & External APIs:
- MongoDB Atlas (for LangGraph state persistence and session tracking)
- Google Sheets API (`gspread`) for CRM
- Cloudinary (for audio hosting)

4. LANGGRAPH WORKFLOW DESIGN (The Brain of the Agent)
-----------------------------------------------------
The agent runs on a cyclic StateGraph with the following nodes:
1. extract_card_data: Parses the incoming image via Gemini Vision.
2. enrich_company: (Parallel process) Derives company metadata.
3. confirm_with_user: **Interrupt Node.** Yields control back to the frontend awaiting manual approval of the extracted data.
4. deduplicate_contact: Checks target Google Sheet for existing records.
5. write_to_sheets: Appends the verified, unique contact.
6. process_voice_note: (Conditional) If audio is received, transcodes to base64, fetches a summary, uploads to Cloudinary, and updates the specific row in Google Sheets.

6. POTENTIAL INTERVIEW QUESTIONS & ANSWERS
------------------------------------------
Q: Why did you choose FastAPI for the backend?
A: FastAPI provides excellent support for asynchronous operations, which is crucial when dealing with multiple external APIs (Gemini, Google Sheets, Cloudinary, MongoDB). It also offers automatic interactive API documentation and high performance.

Q: How does the Human-in-the-Loop (HITL) feature work in LangGraph?
A: In LangGraph, we define an "Interrupt Node" (`confirm_with_user`). When the graph execution reaches this node, it halts and saves its state (checkpoint) to MongoDB. The frontend retrieves the extracted data, allows the user to review/edit it, and then sends a resume signal back to the backend to continue the workflow with the verified data.

Q: How do you handle session management and state persistence?
A: We use MongoDB to store the LangGraph checkpoints and session data. This allows the backend to be stateless, ensuring that if a user refreshes the page, or if there are multiple users, the state of their specific workflow is preserved and easily retrieved using a session ID.

Q: What was the purpose of using Cloudinary?
A: Since Google Sheets is not designed to store large media files, we upload the raw audio voice notes to Cloudinary. Cloudinary provides a secure URL for the audio file, which we then store in the Google Sheet alongside the text summary for easy access.

Q: How did you implement deduplication?
A: Before writing to the Google Sheet, the agent normalizes the extracted phone number and email address. It then checks the existing rows in the Sheet for matches. If a match is found, it prevents creating a duplicate entry.

Q: Why use LangGraph instead of standard LangChain?
A: LangGraph allows for creating cyclic, stateful workflows which are essential for true agentic behavior. It naturally supports features like state persistence, branching logic, and pausing execution for human feedback, which were required for this project.
